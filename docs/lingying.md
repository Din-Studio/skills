# 灵影 CLI 到独立技能的迁移

调研日期：2026-09-27。源码依据为本地 `lingying-cli` 的 `daac133d7795fbb3ec70028f9046fc4b70bd0daf` 版本及当前工作区。交付 `skills/lingying/ly-image` 和 `skills/lingying/ly-video` 两个可单独安装的技能，不要求用户安装原 Go CLI。

## 源码分析与迁移范围

原 CLI 的媒体链路集中在 `cmd/media.go` 和 `internal/client/gateway.go`：先发现模型，按 `model_type` 选择图片或视频端点，用服务端 `model_id` 提交 `input_data`，轮询任务，提取结果链接并下载。`internal/auth/config.go` 负责环境变量与配置文件的凭据优先级，`cmd/task.go` 支持凭任务 ID 查询。

| 原工具能力 | 技能中的实现 |
| --- | --- |
| `image` / `image_edit` | `ly-image` 的动态模型发现、生成与编辑 |
| `video` / `video_edit` | `ly-video` 的动态模型发现、生成与编辑 |
| `model list` / `model info` | `models` / `models --model`，列表只输出简要信息，详情保留 schema、特性和计费信息 |
| `--param` 字符串转换 | UTF-8 请求 JSON 的原生类型，支持嵌套对象和数组 |
| `-i` 推测输入字段 | `inputs` 明确绑定 schema 字段，支持字符串与数组，保持素材顺序 |
| 本地文件上传 | 小文件 SHA-256 去重、预签名 PUT、大文件四并发分片、完成确认与直链获取 |
| `--dry-run` | 模型发现和本地检查，无上传、无生成提交 |
| 同步等待 / `--no-wait` | 提交与查询分离，任务记录先落盘，查询可跨进程继续 |
| 结果下载 | 多结果、无应用鉴权的签名链接下载、临时文件与唯一文件名 |
| 凭据与项目归因 | 兼容环境变量、原配置路径和 `LY_CONFIG_FILE`；支持 `LY_PROJECT_ID` / `--project` |

文本、音频生成、交互登录、自动更新和 CLI 安装器不属于这两个技能的范围。原工具的配置仍可读取，但技能不写入或刷新凭据。媒体编辑能力只有在模型当前 schema 支持时可用，不能从一个 `video` 类型推断它一定接受图片、音频或首尾帧。

## 设计依据

采用标准 `name`、`description`、`compatibility` 与正文，不绑定特定 agent 的工具权限、插件根目录变量或子代理能力。每个技能的所有运行资源都在自身目录内，适配被安装器扁平化后的路径。[Agent Skills 规范](https://agentskills.io/specification)

入口分别描述生图与生视频的触发范围，正文保留任务决策、模型选择和恢复流程。参数与协议细节放入按需读取的参考文档，脚本负责确定性的调用。这个拆分以真实 CLI 的协议和失败模式为依据，符合官方建议的明确职责、渐进披露和执行后改进。[技能编写最佳实践](https://agentskills.io/skill-creation/best-practices)

脚本默认输出 JSON，提供非交互输入、帮助、dry-run 和非零失败退出码。提示词通过文件传递，避免 shell 引号或命令替换改变内容；每次提交使用独占创建的任务记录，防止 agent 重试同一路径时再次生成。[技能脚本设计](https://agentskills.io/skill-creation/using-scripts)

将结构校验、协议行为、真实安装、模型触发与真实服务验证分开记录。测试用具体请求和可观测结果判定，通过格式校验不能证明生成质量；也不把一次测试表述为稳定的触发率。[技能评测建议](https://agentskills.io/skill-creation/evaluating-skills)

以上网页为调研日实际读取的官方文档，不代表未来版本承诺。Claude 插件发现与命令命名另外对照了 [Claude Code skills 文档](https://code.claude.com/docs/en/skills)。

## 异步任务的边界

`generate` 在上传前创建任务记录，提交前写入 `submitting`，收到 ID 后写入 `submitted`。同一路径不能再次提交。`task` 只查询和下载，不创建任务。

这不是服务端幂等保证：如果 Gateway 已接收任务而连接在返回 ID 前断开，本地无法确定结果。此时保留 `submission_unknown`，要求核对网关记录；不能换一个记录名就自动重试。已知任务 ID 时，轮询超时和下载失败都恢复同一任务。任务记录保留提交身份，最新状态始终来自服务端。

模型 schema 是主要约束来源。脚本检查常见类型、必填项、枚举、数值范围和数组数量，不实现完整 JSON Schema。组合规则、格式、引用及供应商附加约束由 Gateway 最终校验。远程结果的常规 URL 字段在 `data.result` 内递归收集，避免把输入素材当成输出。

## 自包含与维护

公共运行时只有一份维护源：`scripts/lingying/runtime.mjs`。`npm run sync` 把它复制到两个技能中，再同步插件清单；`npm run check` 同时检查副本漂移。分发中的两份代码是为了独立安装，不能手工分别维护。

技能脚本只依赖 Node.js 内置模块。用户文件路径以请求 JSON 所在目录为基准，任务记录和输出路径以调用工作目录为基准。安装目录只读，原仓库路径不进入运行逻辑。两个技能各自携带原 CLI 的 MIT 许可声明，仓库其他内容的许可不因此改变。

## 验证

`tests/lingying.test.mjs` 使用本地 HTTP 服务模拟 Gateway 和对象存储，执行实际脚本进程。覆盖独立技能复制、发现与请求预览、类型错误、上传去重、50 MiB 分片、项目头、存储请求鉴权隔离、提交不确定、并发去重、任务失败、等待到期、多个结果和下载恢复。测试不会向生产服务提交任务。

维护验证命令：

```bash
npm run sync
npm run check
npx --yes skills@1.7.0 add . --list
npm run test:install -- --claude
```

真实服务先完成了模型列表、模型详情和 dry-run 验证。随后使用用户授权的测试凭据完成各一次生图与图生视频，覆盖真实上传、生成提交、轮询和下载。凭据通过隐藏终端输入仅传入子进程环境，没有写入仓库、任务记录或报告。

### 真实服务样例

| 项目 | 生图 | 图生视频 |
| --- | --- | --- |
| 模型 | `nanobanana2` | `seedance2.0 fast` |
| 请求 | 1K、1:1，窗边橘猫 | 使用生成图片作为本地参考图，480p 档位、1:1、4 秒、关闭音频 |
| 任务 ID | `e079e259-caba-4f51-a0ad-e753fcec121a` | `a40bc998-7afe-46b4-87eb-50c191999d7c` |
| 实际文件 | PNG，1024×1024 | MP4 / H.264，640×640，4.041667 秒，1,013,609 字节，无音轨 |
| 检查 | 橘猫、木桌、窗边暖光与请求一致 | 首末抽帧保留猫与场景，头部从正面转向窗户；未进行逐帧质量评测 |

视频的 `480p` 是模型接受的服务档位，实际像素尺寸以返回文件为准，本次为 640×640。等待期间多次返回 `running` 和 `wait_expired`，始终恢复同一任务 ID，没有重新提交。测试产物和本地任务记录保留在已忽略的 `temp_data/lingying-live-ykobyk2z/`，不作为发布技能资源。
